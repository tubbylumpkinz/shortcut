How to make every website feel twice as fast

Most of the slowness you feel is not your connection. It's scripts, fonts and a browser working against you. Here's the fix list.

S By The editors October 14, 2026 9 min read

You know the feeling. A page starts to render, then stalls, then reflows as a font arrives late. A chat bubble slides in from the corner. You scroll and the layout jumps under your thumb. It feels like a bad connection, but most of the time it is not.

Modern pages are heavy because they are assembled from a dozen companies' scripts, each one convinced it is the most important thing on the page. You cannot fix the site. You can fix what your browser allows it to do.

Measure first, then subtract

Open DevTools with F12, go to the Network panel, tick Disable cache, and hard-reload with Ctrl / ⌘ + Shift + R. Sort by size, then by time. Most of what you see will come from domains that are not the one in the address bar: tag managers, analytics, support widgets, consent platforms.

You are looking for two numbers: how long until the first meaningful paint, and how many requests happen after the page looks ready. The second number is why a page keeps twitching after it has apparently loaded.

Rule of thumb

A page that feels instant on your laptop can take three times as long on a mid-range phone. Test with throttling on — DevTools has a preset for exactly this reason.

Fonts are the usual suspect

A single typeface can arrive as six separate files: regular, medium, semibold, italic, and so on. Each one is a blocking download that can cause invisible text, then a reflow when it lands. The fix is boring and effective: ship fewer weights, and tell the browser what to do while it waits.

CSS
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter-var.woff2") format("woff2");
  font-weight: 400 600;      /* one variable file, not six */
  font-display: swap;        /* show fallback text immediately */
}

If you are building rather than browsing, start with the system stack and only add a webfont when the design genuinely needs it:

CSS
font-family: ui-sans-serif, system-ui, -apple-system,
             "Segoe UI", Roboto, sans-serif;

Cut the scripts you never asked for

A content blocker is the highest-leverage thing on this list. On a news site it will typically remove between a third and two thirds of all requests, and with them most of the layout shift. uBlock Origin is the reference implementation; Brave ships an equivalent set of shields; Safari users can add an ad blocker extension.

Then audit your own extensions. Every one you install gets to run code on every page, and some of them are quietly enormous. Open the extensions page, sort by what you actually used this month, and remove the rest. This takes ten minutes and is worth more than any "speed up your browser" utility.

Make the network boring again

DNS lookups are usually fast, but a bad resolver adds a stall to the start of every new domain — and a page can touch a dozen. Switching to a well-run resolver such as Cloudflare's 1.1.1.1 or Quad9 takes two minutes in your network settings and removes a class of random delay.

Enable encrypted DNS if your browser or OS offers it. It does not make you anonymous, but it stops your local network from reading every hostname you visit, and it usually comes with a faster resolver as a side effect.

The eighty-twenty list

ChangeWhat it fixesTime
Install a content blockerMost third-party requests and shifts2 min
Use reader mode for long readsStrips scripts, ads and layout0 min
Switch DNS resolverLookup stalls on new domains5 min
Trim browser extensionsCode injected into every page10 min
Disable autoplayVideo decoding, surprise audio1 min
Limit webfont weightsBlocking downloads and reflow10 min

When it is still slow

Sometimes the server is the problem: a cold cache, a distant region, a database query that takes two seconds before the first byte. Nothing on your machine will fix that. Reader mode will at least give you the text while the rest of the page argues with itself.

The mental shift that helps is this: speed is a subtraction exercise, not an addition one. Every extension, font and widget is something the browser has to do before it can show you words. Take things away until it feels fast, then stop.
